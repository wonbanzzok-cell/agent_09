# mk-ppt

`python-pptx`로 PowerPoint 파일을 만들고 수정한다. 이 스킬은 이 저장소의 `.claude/skills/`에 있으므로 여기에서만 불러와지고, 만든 결과물도 모두 이 저장소 안에 둔다.

작업의 형태는 항상 같다. Python 빌드 스크립트를 작성하고, 실행하고, 결과를 다시 열어 확인한다. 일회성 명령 대신 스크립트를 남기는 이유는 발표자료가 여러 번 고쳐지기 때문이다. 스크립트가 있으면 다음 버전은 처음부터 다시 만드는 일이 아니라 작은 수정이 된다.

## 시작하기 전에

- `.claude/rules/ppt-rule-v1/ppt-rule-v1.md`의 PPT 규칙을 먼저 적용한다. 이 규칙은 이 스킬보다 우선한다. 규칙이나 규칙이 가리키는 디자인 참고 자료가 이 파일과 다르면 그쪽을 따른다.
- `CLAUDE.md`의 작업 절차를 따른다. 할 일 목록을 보고하고, 승인을 기다리고, 구조 정리로 마무리한다. 슬라이드 개요(아래 3단계)를 할 일 목록에 넣어, 만들기 전에 사용자가 내용을 승인하게 한다.
- `python -c "import pptx; print(pptx.__version__)"`로 라이브러리를 확인한다. import가 실패하면 말없이 설치하지 말고 `python -m pip install python-pptx`를 할 일 목록에 넣는다.

## 파일 위치

| 항목 | 위치 |
|---|---|
| 발표자료 | `presentation/<주제>_발표자료_v<N>.pptx` |
| 빌드 스크립트 | `scripts/build-presentation-v<N>.py` |
| 발표자료용으로 만든 이미지 | `presentation/assets/v<N>/` |
| 임시 파일 | 세션 스크래치패드. 저장소에는 두지 않는다 |

- `presentation/`은 첫 발표자료를 만들 때 생성한다.
- 기존 발표자료를 덮어쓰지 않는다. 기존 최고 버전의 다음 번호를 쓰고, 이전 빌드 스크립트를 새 버전 번호로 복사한 뒤 고친다.
- 조사 노트나 보고서를 바탕으로 만든 발표자료는, 그 번호가 비어 있으면 원본과 같은 버전 번호를 쓴다.
- 사용자가 따로 요청하지 않으면 슬라이드 내용은 `report/`의 보고서와 같이 한국어로 쓴다.

## 작업 순서

1. **내용을 확정한다.** 원본(조사 노트, 보고서, 또는 사용자의 메시지), 청중, 대략의 슬라이드 수를 파악한다. 답에 따라 발표자료가 달라질 때만 질문한다.
2. **파일이 이미 있으면 먼저 살펴본다.** 수정이나 템플릿 작업이라면 코드를 쓰기 전에 검사 스크립트를 실행한다. 플레이스홀더 인덱스와 레이아웃 이름은 파일마다 달라서 추측하면 실패한다.
   ```
   python .claude/skills/mk-ppt/scripts/inspect_pptx.py <file.pptx>
   ```
3. **슬라이드 개요를 짠다.** 슬라이드마다 한 줄씩 제목, 전달할 요점, 구성 요소(글머리 기호, 표, 차트, 그림)를 적는다. 이를 할 일 목록에 넣어 보고한다.
4. **빌드 스크립트를 작성한다.** `scripts/build-report.js`처럼 출력 경로 하나만 인자로 받는다. `references/python-pptx-api.md`의 기본 틀에서 시작한다.
5. **저장소 루트에서 실행한다.**
   ```
   python scripts/build-presentation-v<N>.py "presentation/<주제>_발표자료_v<N>.pptx"
   ```
6. **검증한다.** 결과 파일에 검사 스크립트를 실행해 개요와 비교한다. 슬라이드 수, 제목, 빈 플레이스홀더가 없는지, 슬라이드 밖으로 나간 도형이 없는지 본다. 파일을 손으로 고치지 말고 스크립트를 고쳐 다시 만든다.
7. **보고하고 정리한다.** 무엇을 만들었고 무엇을 하지 못했는지 사용자에게 알린 뒤, `CLAUDE.md`와 번역본의 구조도와 표를 고친다.

## 기본 디자인

사용자, PPT 규칙, 디자인 참고 자료, 템플릿이 정하지 않은 항목에만 다음을 쓴다.

- **크기:** 16:9, `13.333 x 7.5`인치. 내장 기본 템플릿은 4:3이므로 크기를 직접 지정한다.
- **레이아웃:** 빈 레이아웃(기본 템플릿의 `slide_layouts[6]`)에 텍스트 상자를 좌표로 배치하면 결과를 예측하기 쉽다. 사용자의 템플릿을 채울 때는 템플릿의 디자인이 유지되도록 플레이스홀더를 쓴다.
- **여백:** 내용을 모든 가장자리에서 0.5인치 이상 띄운다.
- **글꼴:** `맑은 고딕`. 제목 32–40pt, 본문 18–24pt, 캡션은 12pt 이상.
- **분량:** 슬라이드 하나에 요점 하나, 글머리 기호는 다섯 개 정도까지. 자세한 내용은 발표자 노트로 옮긴다.
- **색:** 강조색 하나와 무채색. 스크립트 맨 위에 상수로 한 번만 정의한다.

## 자주 생기는 문제

- **한글이 다른 글꼴로 표시된다.** `font.name`은 라틴 글꼴만 지정한다. 참고 문서의 `set_font_name` 헬퍼로 동아시아 글꼴도 함께 지정한다.
- **텍스트가 상자를 넘친다.** 라이브러리는 텍스트 크기를 재지 않고, PowerPoint는 파일을 열어 편집할 때만 자동 맞춤을 적용한다. 상자를 넉넉하게 잡고 글자 크기를 직접 지정한다.
- **16:9 발표자료에서 플레이스홀더가 한쪽으로 치우친다.** 슬라이드 크기를 바꿔도 기본 템플릿의 플레이스홀더는 움직이지 않고 4:3 레이아웃의 위치에 그대로 있다. 빈 레이아웃에 텍스트 상자를 쓰거나, 플레이스홀더마다 위치와 크기를 지정한다.
- **플레이스홀더를 찾지 못한다.** 목록에서의 순서가 아니라 검사 스크립트 출력에 나온 `placeholder_format.idx`로 찾는다.
- **저장할 때 `PermissionError`가 난다.** 파일이 PowerPoint에서 열려 있다. 사용자에게 닫아 달라고 요청한다. 다른 이름으로 저장해 피해 가지 않는다.
- **크기가 이상하다.** 길이는 EMU 정수다. 숫자는 항상 `Inches()`, `Cm()`, `Pt()`로 감싼다.
- **차트가 만들어지지 않는다.** 계열 값은 숫자(또는 `None`)여야 하고, 모든 계열에 범주마다 값이 하나씩 있어야 한다.

## 라이브러리가 할 수 없는 일

사용자가 다음을 요청하면 할 수 없다고 분명히 말하고, 가능한 것 중 가장 가까운 방법을 제안한다.

- 애니메이션과 화면 전환
- SmartArt 생성, 수식 편집
- 슬라이드를 이미지나 PDF로 렌더링
- 구형 `.ppt` 파일과 암호가 걸린 파일
- 메모(댓글)

슬라이드 삭제·순서 변경·복제, 도형 삭제, 앞뒤 순서 변경, 표의 행 추가·삭제는 공식 API가 없지만 XML을 직접 고쳐서 할 수 있다. 참고 문서에 각각에 대해 테스트한 코드가 있다.
